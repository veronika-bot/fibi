## Требования платежной системы (из дизайна for-tutors.html)

### Основной флоу
1. **Запись ученика**: Ученик находит репетитора в каталоге → пишет в чат → предлагает время
2. **Оплата**: Ученик оплачивает занятие через платформу (до начала или по факту)
3. **Управление средствами**: ФИБИ удерживает средства и выплачивает репетитору после подтверждения состоявшегося занятия
4. **Выплата**: Выплата репетитору в течение 24 часов после подтверждения занятия
5. **Вывод средств**: Накопленная сумма выводится на банковскую карту по запросу или автоматически

### Ключевые особенности
- **Комиссия платформы**: фиксированная (размер не указан — определить)
- **Безопасность**: защита обеих сторон
  - Ученик получает гарантию оплаты
  - Репетитор получает защиту от споров
- **Прозрачность**: никаких скрытых вычетов
- **Условия использования**: работа вне платформы нарушает условия (явное требование)

### Требования по таким условиям (for-students.html)

#### Свободный тариф (0 ₽)
- Часть заданий из банка
- Базовый прогресс и серии
- Пробные подсказки ИИ

#### Тариф «Самостоятельная подготовка» (679 ₽/месяц)
- Полный банк заданий
- Персональный план на год
- ИИ-помощник без ограничений
- Полная карта знаний
- Демоварианты и решения
- Материалы для самоподготовки

#### Занятия с репетитором
- Оплата по стоимости занятия (через платформу)
- Включает все из «Самостоятельной»
- Проверка заданий 2-й части
- Индивидуальный план занятий

## Структура реализации

### 1. Базовые модели данных
```
- Payment (платеж)
  - id, studentId, tutorId, amount, status, date
  - status: pending, completed, refunded, disputed
- Subscription (подписка ученика)
  - id, studentId, planId, status, expiryDate, autoRenew
- TutorBalance (баланс репетитора)
  - id, tutorId, balance, pendingBalance, totalEarned
- PaymentMethod (способ оплаты)
  - id, userId, type (card, bank_account), details
- Transaction (транзакция)
  - id, paymentId, type (charge, payout), status, date
```

### 2. API endpoints (для Next.js backend)

#### Ученику:
- `POST /api/payment/subscribe` — купить подписку
- `POST /api/payment/session` — создать платежную сессию
- `GET /api/payment/methods` — получить способы оплаты
- `POST /api/payment/methods` — добавить способ оплаты
- `GET /api/payment/history` — история платежей

#### Репетитору:
- `GET /api/tutor/balance` — баланс и статистика
- `GET /api/tutor/transactions` — список выплат
- `POST /api/tutor/withdraw` — запросить выплату
- `POST /api/tutor/bank-account` — добавить реквизиты

#### Интеграция платежей:
- `POST /api/payment/webhook` — вебхуки от платежной системы (YooKassa/Stripe)
- `POST /api/payment/confirm` — подтверждение платежа
- `POST /api/lesson/confirm` — подтверждение состоявшегося занятия → автоматическая выплата

### 3. Frontend компоненты

#### Для ученика:
- Экран выбора тарифа с процессом оплаты
- Модальное окно добавления способа оплаты
- История платежей
- Статус подписки

#### Для репетитора:
- Баланс и статистика заработков
- История выплат с фильтрами
- Форма вывода средств
- Добавление реквизитов банка

#### Для администратора:
- Панель управления платежами
- Решение споров
- Отчеты по выплатам и комиссиям

### 4. Интеграция с платежной системой
- Выбрать: YooKassa (рекомендуется для РФ), Stripe (международное)
- Использовать официальные SDK
- Обработка вебхуков для подтверждения платежей
- Тестовый режим перед продакшеном

### 5. Бизнес-логика

#### Оплата подписки (679 ₽/месяц):
```
Сумма платежа: 679 ₽
Комиссия платформы: ~5% = 34 ₽
Чистый доход: 645 ₽
```

#### Оплата занятия с репетитором:
```
Ученик платит: X ₽
Комиссия платформы: Y% (фиксированная, определить размер)
Репетитор получает: X - (X * Y%)
Выплата репетитору: в течение 24 часов
```

#### Автоматические выплаты:
- После подтверждения занятия → накопление на балансе репетитора
- По расписанию (напр., по пятницам) или по запросу

### 6. Безопасность

#### Требования:
- PCI DSS compliance для обработки карт (или использовать стороннего провайдера)
- Шифрование чувствительных данных (API ключи, реквизиты банка)
- Двухфакторная аутентификация для вывода средств
- Логирование всех транзакций
- Защита от мошенничества (лимиты на снятие, верификация банка)

### 7. Тестирование

#### Unit tests:
- Расчет комиссий
- Статусы платежей
- Логика выплат

#### Integration tests:
- Полный цикл платежа (от покупки подписки до выплаты)
- Вебхуки платежной системы
- Обработка ошибок и refund'ов

#### E2E tests:
- Покупка подписки (UI)
- Запрос выплаты репетитором (UI)
